# 数据库可靠性改进记录

本轮按「旧库与恢复 → 中断回退 → 查询测量 → 连接配置」推进。保留 SQLite、Drift、统一数据库入口和现有搜索规则，没有更换数据库，也没有提升数据库版本号。

## 已完成

1. **旧资料能继续打开**：固定保存一份 v1 数据库 SQL 测试样本，包含九张普通表及关联数据。验证旧库读取、拒绝未来版本，以及拒绝时保留原资料。
2. **恢复前先检查备份**：检查备份格式、数据库版本、普通表的字段和完整性、关联关系。缺失、空文件和损坏数据库不能被自动建成新库后覆盖本地资料。合并恢复继续允许已有的孤儿记录跳过策略。
3. **新备份可核对文件是否齐全**：保存数据库和附件的 SHA-256 校验值，恢复前核对。打包前后检查数据库写入计数、外部连接版本和附件内容；发现变化则拒绝发布此次归档。不同次备份使用独立临时文件，备份与恢复不能重叠执行。
4. **恢复失败能回退**：完整恢复、文库恢复和文库合并都保留旧数据库与旧文件，成功后才清理。磁盘上的未完成标记支持下次启动回退。数据库更换后，即使恢复失败，也会刷新旧订阅。后台任务未结束时停止恢复。
5. **轻量备份恢复不误丢本地 PDF**：用恢复后的数据库记录判断要保留哪些文献，不再用 ZIP 中是否有目录判断。没有 PDF 的条目明确标记为无文件。
6. **导入、删除不再只完成一半**：删除先暂存文件，数据库删除失败就放回；导入入库失败只清理此次复制的文件，保留原始文件。启动时根据数据库记录处理未完成的文件操作。
7. **设置写入失败不假装成功**：数据库写入、删除成功后才更新内存设置；失败时仍显示原值。
8. **减少查询的无用工作**：启动计数由数据库直接返回，搜索复用现有输入防抖器。索引数量相同但 ID、rowid 或内容不匹配时仍会修复；重建在事务内完成。保留原有 FTS/jieba 和全字段 LIKE 搜索结果。
9. **明确保存规则**：文件连接每次打开都启用 WAL、外键和 `synchronous=FULL`，包含恢复后的重新打开。没有增加会同步阻塞界面的锁等待时间。
10. **大附件解压边读边写**：不再先把整个 ZIP 和每个附件完整读入内存。新增错误提示包含中英文 ARB，并已生成本地化代码。

## 测量与验证

计数比较使用本机 Flutter 测试环境、内存 SQLite 和合成文献，每档预热一次、测量二十次。下面仅是计数操作的耗时，不是应用启动时间。

| 文献数 | 全表读取后计数 p50 / p95 | SQL 计数 p50 / p95 |
| --- | --- | --- |
| 1,000 | 2.931 / 5.499 ms | 0.144 / 0.315 ms |
| 10,000 | 31.434 / 36.923 ms | 0.292 / 0.424 ms |
| 50,000 | 148.525 / 157.801 ms | 0.296 / 0.358 ms |

重跑测量：`flutter test --no-pub test/core/storage/database_query_benchmark_test.dart`。

回归覆盖旧库、无效备份、附件缺失、备份期间写入、恢复途中失败、下次启动回退、32 MiB 附件往返、导入和删除失败、设置写入失败、索引修复及既有搜索/合并行为。所有数据均来自临时测试目录。

初轮数据库改进的 59 项相关回归测试通过。提交审查补充了同文献并发文件操作、无进度条任务阻止恢复、并发提取用量及取消等场景；存储、OCR、阅读器和桌面交互共 242 项回归测试通过，计划提交的 72 个 Dart 文件及测试静态分析无问题。

审查首轮全量测试为 451 项通过、3 项跳过、2 项失败。MinerU 轮询测试的 Flutter binding 初始化已修复；原有 `test/utils/desktop_test.dart` 引用不存在的 `desktopActivator`，仍是完整测试套件的已知失败项。审查期间其他会话新增的翻译和主页面改动未纳入本次提交。

## 边界

- 备份变动检查会增加磁盘读取；合并的可回退副本也需要额外临时空间。32 MiB 往返测试不代表已经测过多 GB 文库的峰值内存。
- 这是应用层的变动检测和恢复记录，不是操作系统提供的瞬时文件系统快照；未进行真实设备断电测试。
- 单测环境缺少 `simple.dll`。索引同步使用 SQLite 内置分词器验证，中文 LIKE 路径通过；原生 jieba/拼音仍需设备端检查。
- 尚未改造列表分页或数据库后台执行。现有测量支持消除全表计数，但不足以验证这两项更大改动的收益和设备兼容性。
- 仓库 `.gitignore` 忽略整个 `/test`。本次按明确文件清单纳入相关回归测试和固定样本，保留该忽略规则；本地测试脚本及凭据未纳入提交。

新增测试主要位于 `test/core/storage/`、`test/services/backup_restore_test.dart`、`test/services/backup_restore_lifecycle_test.dart` 和 `test/providers/document_file_failure_test.dart`；固定旧库样本为 `test/core/storage/fixtures/schema_v1.sql`。
